# 先讓它能動再讓它正確

**定義**：先寫出能執行的程式碼，再逐步清理讓它變好（[[Clean Code 02 清理你的程式碼]]）。
這裡的「正確」指結構良好、整潔，不是功能正確（ingest Clean Code 01 時你確認的解讀）。

## 各來源怎麼說

### Clean Code 第 1 章

> 不用追求完美的程式碼，而是讓程式碼舒適

（重點，[[Clean Code 01 無瑕的程式碼]]）

> 先讓程式碼能運作再讓它正確

（書中引文，[[Clean Code 01 無瑕的程式碼]]）

### Clean Code 第 2 章

> 先讓程式碼能動，再逐步清理程式碼

（一句話總結，[[Clean Code 02 清理你的程式碼]]）

> 先寫出一份能執行的程式碼，接著再透過不斷調整，讓它逐漸變得更好

> 將類似的程式碼提取成函式

> 建立內部物件避免把引數傳來傳去給輔助函式

> 不要寫出太聰明、複雜，那樣反而不好

（重點，[[Clean Code 02 清理你的程式碼]]）

> 49NGO這種字元替換太聰明的寫法反而不自然，感覺別人要花許久才會讀懂

（例子，[[Clean Code 02 清理你的程式碼]]）

- 與既有內容的關係：**新增**。第 1 章提出原則，第 2 章補上具體的清理手法。
