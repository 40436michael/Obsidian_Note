# 先讓它能動再讓它正確

**定義**：先寫出一份能執行的程式碼，再透過不斷調整，讓它變得整潔。不要一開始就追求完美（[[Clean Code 02 清理你的程式碼]]）。

> 先讓它能運作，再讓它正確，或至少更好。（[[Clean Code 02 清理你的程式碼]]）

這句話在兩章都出現：第 1 章引用時，這裡的「正確」指的是結構良好、整潔，不是功能正確（[[Clean Code 01 無瑕的程式碼]]）。

## 各章怎麼談這個做法

- **第 1 章**：目標是讓程式碼好讀好改，而不是完美（[[Clean Code 01 無瑕的程式碼]]）。
- **第 2 章**：用一個重構範例示範實際的清理過程，重點是「能動之後，逐步調整」（[[Clean Code 02 清理你的程式碼]]）。

## 清理時的具體手法（第 2 章）

- 把類似的程式碼提取成函式。
- 建立內部物件：原本在輔助函式之間傳來傳去的引數，改成物件自己的欄位。
- 避免太聰明、太複雜的寫法，這種寫法很可能只是自我放縱（[[Clean Code 02 清理你的程式碼]]）。

## 我的看法

書中範例裡把字元替換寫得太聰明的做法（如 49NGO），我覺得反而不自然，別人要花很久才讀得懂（[[Clean Code 02 清理你的程式碼]]）。
